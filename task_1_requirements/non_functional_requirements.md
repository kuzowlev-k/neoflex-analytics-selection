## 1. Производительность (Performance)

| Номер | Требование                                                                                                                                                 | Способ проверки                                                          |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1.1   | Время загрузки главной страницы https://edu.neoflex.ru/ — не более **2 секунд** при скорости соединения от 10 Мбит/с.                                      | Замеры через Google Lighthouse                                           |
| 1.2   | Время открытия модального окна формы после клика по кнопке «Хочу учиться» — не более **1 секунды**.                                                        | Замер TTFB + рендеринг                                                   |
| 1.3   | Время обработки отправки формы и возврата ответа сервера — не более **2 секунд** при нормальной нагрузке.                                                  | Нагрузочное тестирование  через Gatling                                  |
| 1.4   | Система должна выдерживать **не менее 1000 одновременных пользователей** на форме без деградации времени отклика выше порогов описанных в пунктах 1.1–1.3. | Нагрузочный тест через Gatling, имитация 1000 виртуальных пользователей. |
| 1.5   | Система должна корректно работать при пиковой нагрузке **до 5000 заявок в сутки** (в период открытия набора).                                              | Стресс-тест, проверка Error Rate ≤ 0,1 %.                                |
| 1.6   | Потребление памяти и CPU не должно расти линейно при длительной работе (отсутствие утечек в БД, кэше, глобальных переменных, которые накапливают данные).  | Длительный тест 24 ч и мониторинг.                                       |

## 3. Надёжность и доступность (Reliability & Availability)

| Номер | Требование                                                                                                     | Способ проверки                                         |
| ----- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 3.1   | Доступность формы — не менее **99,5 %** времени в сутки. Допустимый простой — не более **7 мин 12 с в сутки**. | Мониторинг uptime, расчёт SLA.                          |
| 3.2   | Система должна автоматически восстанавливаться после сбоя сервера **без потери уже отправленных заявок**.      | Chaos-тест: отключение БД, проверка сохранности данных. |
| 3.3   | Все ошибки отправки формы должны логироваться с указанием: времени, IP, типа ошибки, ID заявки.                | Проверка логов, анализ инцидентов.                      |
| 3.4   | При недоступности сервера пользователь видит сообщение «Сервис временно недоступен, попробуйте позже».         | Ручное тестирование с имитацией ошибки 5xx.             |

## 4. Безопасность (Security)

| Номер | Требование                                                                             | Способ проверки                            |
| ----- | -------------------------------------------------------------------------------------- | ------------------------------------------ |
| 4.1   | Передача всех данных формы — только по **HTTPS** (TLS 1.2+).                           | Проверка сертификата через SSL Labs.       |
| 4.2   | Защита от автоматических спам-отправок: **CAPTCHA**.                                   | Тест-бот, проверка блокировки.             |
| 4.3   | Персональные данные хранятся в **зашифрованном виде** в соответствии с **152-ФЗ**.     | Проверка шифрования в БД, логах            |
| 4.4   | Ограничение количества отправок формы с одного IP/email в заданный промежуток времени. | Тест частых запросов, проверка 429 ошибки. |
| 4.5   | Защита от OWASP Top 10: SQL-инъекции, XSS.                                             | Сканер уязвимостей, пентест.               |

## 6. Удобство использования (Usability)

| Номер | Требование                                                                                            | Способ проверки                            |
| ----- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 6.1   | Заполнение формы — не более **2 минут**.                                                              | Юзабилити-тест с реальными пользователями. |
| 6.2   | Ошибки валидации отображаются рядом с полем **без перезагрузки страницы**.                            | Ручное тестирование.                       |
| 6.3   | Обязательные поля визуально выделены **до начала заполнения**.                                        | Визуальная проверка.                       |
| 6.4   | Фокус сохраняется на активном поле при появлении ошибки.                                              | Ручное тестирование.                       |
| 6.5   | Экран подтверждения «Заявка успешно отправлена!» появляется **не более чем за 2 секунды**.            | Замер времени.                             |
| 6.6   | Возможность закрыть форму в любой момент без отправки данных (Esc, крестик).                          | Ручное тестирование.                       |
| 6.7   | При клике на ссылки политики конфиденциальности форма **не закрывается**, данные в форме сохраняются. | Ручное тестирование.                       |

## 9. Ограничения и допущения

- Форма работает в режиме «Набор закрыт» — данные сохраняются в БД для последующего информирования.
- Отправка письма-подтверждения — в течение **1 минуты** после успешного сохранения заявки.
- Повторная отправка с тем же email блокируется.
